# Core AI Agent Principles (Bộ Nguyên Tắc Cốt Lõi)

All AI agents and workflows operating in this project MUST strictly follow these core principles without exception:

## 1. Commit Standards & Zero AI Reference
- **Strict Compliance with `git-manager`**: All git commits must strictly adhere to the guidelines in `.claude/agents/git-manager.md` and the `ck:git` skill (`references/commit-standards.md`).
- **Conventional Commits**: Format must follow `type(scope): description` (e.g., `feat:`, `fix:`, `refactor:`, `test:`, `chore:`, `perf:`). Keep summary under 72 characters, imperative present tense, no trailing period.
- **ZERO AI REFERENCE**:
  - Never include any AI references, mentions, or attribution in commit messages, descriptions, body, or git tags (e.g., DO NOT include "Generated by AI", "Assisted by Claude/Gemini", "Antigravity", "LLM", etc.).
  - Never include `Co-authored-by:` referencing an AI.
  - Commits must appear completely clean, professional, and human-authored.

## 2. Clarification & Confirmation Before Execution (Confirm Before Action)
- **Confirm Before Action**: Before executing or implementing ANY task, you MUST proactively review the requirements and confirm with the user any points that are unclear, ambiguous, or underspecified.
- **No Unchecked Assumptions**: Never make arbitrary assumptions on key features, business logic, UX flows, or architectural decisions. Ask clarifying questions (using `AskUserQuestion` or direct chat inquiry) and obtain user confirmation before writing or modifying code.

## 3. Strict Language Protocol (Quy Định Ngôn Ngữ Bắt Buộc)

### 🗣️ A. Human Communication (Giao Tiếp Với Con Người / CEO)
- **ALWAYS in Vietnamese (Bắt buộc dùng Tiếng Việt)**:
  - All direct interactions, status reports, executive summaries, clarifying questions, and discussions with the user/CEO MUST be conducted in clear, professional Vietnamese.

### 📄 B. Project Documentation & Artifacts (Triển Khai Toàn Bộ Tài Liệu & Mã Nguồn)
- **ALWAYS in English (Bắt buộc dùng Tiếng Anh)**:
  - All project documents, PRDs, technical specifications, architecture blueprints, sprint backlogs, task breakdown lists, implementation plans, code comments, docstrings, variable/type names, test reports, and documentation files (under `docs/`, `plans/`, `teams/`, root `.md` files) MUST be authored in English.
  - **Single Explicit Exception**: The root `README.md` file is kept in Vietnamese as an executive reference overview for the CEO.

### 🤖 C. Inter-Agent Collaboration (Giao Tiếp Giữa Các Agent Với Nhau)
- **ALWAYS in English (Bắt buộc dùng Tiếng Anh)**:
  - All peer-to-peer messaging (`SendMessage`), task delegations, handoffs, subagent invocation prompts, squad execution context passes, and review feedback between agents MUST be strictly in English to maximize precision, prompt caching efficiency, and reasoning performance.
